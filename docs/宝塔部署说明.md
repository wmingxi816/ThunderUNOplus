# 宝塔部署说明

本文按下面这套环境来写：

- 域名：`thunderunoplus.fun`
- 公网 IP：`8.163.34.254`
- 项目目录：`/www/wwwroot/ThunderUNOplus`
- 前端静态目录：`/www/wwwroot/ThunderUNOplus/apps/client-web/dist`
- 服务端端口：`127.0.0.1:8787`

## 先说明核心思路

这套项目不是“宝塔 Node 项目直接跑整个站点”，而是分成两部分：

1. 前端是 Vite 打包后的静态文件，由宝塔 Nginx 提供 `https://thunderunoplus.fun`
2. 服务端是一个 PM2 托管的 Node WebSocket 进程，只在本机监听 `127.0.0.1:8787`
3. 宝塔 Nginx 把 `https://thunderunoplus.fun/ws` 反向代理到 `http://127.0.0.1:8787`
4. SSL 证书只配在宝塔站点上，浏览器访问时自动走 `wss://thunderunoplus.fun/ws`

这样做的好处是：

- SSL 只在宝塔 Nginx 管
- Node 服务端不用自己配证书
- 8787 不需要暴露到公网
- 前端和 WebSocket 都走同一个域名，最稳

## 第 1 步：确认域名解析

在域名后台把这些解析指向你的服务器：

- `A  thunderunoplus.fun  ->  8.163.34.254`
- `A  www.thunderunoplus.fun  ->  8.163.34.254`

如果你只打算用裸域名，也可以只保留第一条。

## 第 2 步：不要混用两套 Nginx

你前面失败的根因，就是“证书配在宝塔 Nginx，但实际跑的是系统 yum 安装的 Nginx”。

所以这次要先确认 80/443 最终是宝塔 Nginx 在监听。

在服务器里检查：

```bash
systemctl status nginx
ss -lntp | grep -E ':80|:443|:8787'
ps -ef | grep nginx
```

如果你发现系统自带的 Nginx 还在跑，先停掉它：

```bash
systemctl stop nginx
systemctl disable nginx
```

然后回到宝塔面板，确认宝塔自己的 Nginx 是启动状态。

重点是：

- 不要让系统 Nginx 和宝塔 Nginx 同时抢 80/443
- 后面所有 SSL 和站点配置，都只在宝塔面板里做

## 第 3 步：准备运行环境

项目要求：

- Node.js `>= 20.11.0`
- pnpm `>= 10.10.0`

建议在宝塔里准备好 Node 20，再进终端执行：

```bash
cd /www/wwwroot/ThunderUNOplus
node -v
corepack enable
```

如果项目还没放到服务器，可以重新拉取：

```bash
cd /www/wwwroot
git clone <你的仓库地址> ThunderUNOplus
cd /www/wwwroot/ThunderUNOplus
```

如果项目已经在服务器，只需要后续执行构建步骤即可。

## 第 4 步：安装依赖并构建

在服务器执行：

```bash
cd /www/wwwroot/ThunderUNOplus
git fetch origin
git checkout main
git pull --ff-only origin main

corepack enable
corepack pnpm install --frozen-lockfile
corepack pnpm --filter @thunder-uno/game-server build
corepack pnpm --filter @thunder-uno/client-web build
```

现在这次的部署建议是：

- 服务端仍然用项目现有的 `tsx src/dev/runLocalServer.ts` 运行
- PM2 负责常驻进程
- 前端仍然使用 `apps/client-web/dist`

之前那条错误命令：

```bash
pm2 start apps/game-server/dist/index.js
```

不要再用了，因为 `dist/index.js` 只是导出模块，不会真正监听端口。

## 第 5 步：启动 PM2 服务端

项目根目录里现在有 `ecosystem.config.cjs`，已经按这套部署方式配好了：

- 进程名：`game-server`
- 工作目录：`/www/wwwroot/ThunderUNOplus/apps/game-server`
- 启动文件：`node_modules/.bin/tsx src/dev/runLocalServer.ts`
- 监听地址：`127.0.0.1:8787`

首次启动：

```bash
cd /www/wwwroot/ThunderUNOplus
pm2 start ecosystem.config.cjs --only game-server
pm2 save
pm2 status
```

以后更新代码时，可以直接跑我加好的脚本：

```bash
cd /www/wwwroot/ThunderUNOplus
chmod +x tools/deploy-bt.sh
./tools/deploy-bt.sh
```

查看日志：

```bash
pm2 logs game-server --lines 100
```

确认服务端已经只在本机监听：

```bash
ss -lntp | grep 8787
```

你应该看到类似：

```txt
127.0.0.1:8787
```

## 第 6 步：在宝塔创建站点

在宝塔面板里新增站点：

- 域名：`thunderunoplus.fun`
- 如果你也要 `www`，把 `www.thunderunoplus.fun` 一起加上
- 根目录：`/www/wwwroot/ThunderUNOplus/apps/client-web/dist`

这是静态站点，不需要把整个项目作为网站根目录。

## 第 7 步：申请并启用宝塔 SSL

在宝塔站点设置里：

1. 打开 `SSL`
2. 申请宝塔/Let's Encrypt 证书
3. 开启“强制 HTTPS”

注意：

- 证书只装在宝塔站点上
- Node WebSocket 服务端仍然是本地明文 `ws://127.0.0.1:8787`
- 浏览器外部访问会被 Nginx 自动升级成 `wss://thunderunoplus.fun/ws`

## 第 8 步：配置宝塔 Nginx

到宝塔站点的 `配置文件` 里，确认 `server { ... }` 内有下面两段关键配置。

如果已有 `location /`，就把它改成下面这种 `try_files` 写法：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}

location /ws {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 600s;
    proxy_send_timeout 600s;
}
```

保存后在宝塔里重载 Nginx。

这两段的作用分别是：

- `location /` 让前端静态资源和 `index.html` 正常打开
- `location /ws` 让浏览器的 `wss://thunderunoplus.fun/ws` 转发到本地 `127.0.0.1:8787`

## 第 9 步：防火墙和安全组

公网只需要放行：

- `80`
- `443`

不建议把 `8787` 暴露到公网，因为现在它只给本机 Nginx 反代使用。

## 第 10 步：上线验证

先看本机服务：

```bash
pm2 status
pm2 logs game-server --lines 50
ss -lntp | grep -E ':80|:443|:8787'
```

再看网站是否正常：

```bash
curl -I http://thunderunoplus.fun
curl -I https://thunderunoplus.fun
```

浏览器里最终要验证这几件事：

1. `https://thunderunoplus.fun` 能打开首页
2. 浏览器控制台没有 `ws://localhost:8787` 这种连接
3. Network 里能看到 WebSocket 连的是 `/ws`
4. 可以创建房间、加入房间、开始对局

## 常见错误对照

### 1. 页面能打开，但无法连上 WebSocket

优先检查：

- `pm2 logs game-server`
- `ss -lntp | grep 8787`
- 宝塔站点 Nginx 里是否真的有 `location /ws`
- 浏览器里连接的是不是 `wss://thunderunoplus.fun/ws`

### 2. SSL 明明申请成功，但访问还是证书不生效

通常就是：

- 80/443 不是宝塔 Nginx 在接
- 系统 yum 安装的 Nginx 还占着端口

### 3. PM2 显示进程在线，但游戏服务其实没起来

通常就是之前那种错误启动方式：

```bash
pm2 start apps/game-server/dist/index.js
```

正确的是：

```bash
pm2 start ecosystem.config.cjs --only game-server
```

或直接手动启动：

```bash
cd /www/wwwroot/ThunderUNOplus/apps/game-server
HOST=127.0.0.1 PORT=8787 node_modules/.bin/tsx src/dev/runLocalServer.ts
```

### 4. 前端仍然去连 localhost

这次我已经把前端默认逻辑改了：

- 本地开发时默认 `ws://localhost:8787`
- 正式 HTTPS 站点默认 `wss://当前域名/ws`

只要站点是通过 `https://thunderunoplus.fun` 打开的，它就会自动走正确的公网 WebSocket 地址。

## 建议的标准部署顺序

每次重装或重新上线，按这个顺序最稳：

1. 确认域名解析到 `8.163.34.254`
2. 停掉系统 Nginx，只留宝塔 Nginx
3. 拉代码并构建前后端
4. 用 PM2 启动 `tsx src/dev/runLocalServer.ts`
5. 在宝塔站点里配置根目录到 `apps/client-web/dist`
6. 宝塔里申请 SSL，并开启强制 HTTPS
7. 在宝塔站点 Nginx 里加 `/ws` 反代
8. 重载 Nginx
9. 打开网站联调
