# Phase 5A：网页端体验与规则入口重修

## 阶段目标

本阶段重点不是修改核心规则，而是把网页端试玩体验继续向“可公开试玩”的方向收口。

主要目标包括：

1. 重修规则讲解入口，让玩家在大厅和对战页都能方便查看规则。
2. 优化连接体验，打开网页后自动连接服务端。
3. 优化大厅视觉，把用户提供的大厅背景图接入页面。
4. 优化对局结束后的普通玩家选择，让房主和非房主在结束弹窗里有不同操作。
5. 继续保持服务端权威、客户端只展示和发送命令的边界。

### 5. 打开网页自动连接

之前需要玩家手动点击连接按钮。

现在页面初始化渲染后，会自动调用一次连接逻辑：

```ts
render();
connectUsingCurrentInputs();
```

连接状态仍然由 WebSocket 事件驱动，不做轮询，不反复刷新状态。

按钮状态改为：

- 连接成功：绿色 `已连接`
- 未连接、断开、错误：红色 `重新连接`

点击红色 `重新连接` 会重新发起连接；如果已经处于 `open` 或 `connecting` 状态，不会重复创建连接。

### 6. 大厅背景图接入

用户在 `pictures/横版背景` 中提供了 `大厅.png`。

本阶段将它复制为：

```txt
apps/client-web/public/lobby-background.png
```

大厅页面通过 `.shell::before` 作为背景层展示，透明度为 `20%`。

对战页使用 `.shell-battle::before` 关闭该背景层，避免影响对战界面的沉浸式牌桌背景。

### 7. 对局结束后的普通玩家选择

此前对局结束后，房主可以选择继续游戏或重开一把；普通玩家只能等待房主操作。

本阶段新增普通玩家结束弹窗按钮：

1. `留在房间`
2. `离开房间`

行为：

- 普通玩家点击 `留在房间`：关闭结束弹窗，继续停留在当前房间和对战页。
- 普通玩家点击 `离开房间`：发送 `leave-room`，然后回到大厅。
- 房主仍然显示 `重开一把` 和 `继续游戏`。

为避免重复逻辑，对战页 HUD 的退出按钮和结束弹窗的离开按钮共用同一个离房函数。
