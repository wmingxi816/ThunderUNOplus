# Problem 3：摸牌、罚抽与质疑流程重构

## 问题背景

当前摸牌和罚抽流程存在几个问题：

1. 普通摸牌后如果摸到可打出的牌，系统会自动打出。
2. 罚抽指定颜色时，系统一次性摸完，没有一张一张展示。
3. 摸牌没有牌落入手牌堆的动画。
4. 刚摸到的牌没有红色提示。
5. 质疑判定可能错误地把刚摸到的牌算进去。

本问题对应原问题：

- 3. 罚抽指定颜色后，下家应一张一张摸并提示颜色
- 4. 摸牌应该有牌落入手牌堆的动画
- 11. 普通摸牌后应询问是否打出，不应自动打出
- 13. 摸牌后刚摸到的牌用红色圈出
- 11. 质疑不应计算刚摸到的牌

## 本阶段目标

重构摸牌相关流程：

1. 普通摸牌后，先加入手牌，再询问是否立即打出。
2. 罚抽指定颜色时，每次只摸一张，并提示摸到的颜色。
3. 摸牌有从牌堆到手牌区的动画。
4. 刚摸到的牌用红色圈出，直到下一个完成出牌。
5. 质疑判定基于摸牌前手牌，不包括刚摸到的牌。

## 不要做什么

本阶段不要做：

- 不做概率洗牌袋。
- 不改 CARD-CONFIG。
- 不做弃牌堆散落动画。
- 不做完整牌桌重构。
- 不做新玩法规则。
- 不做登录、数据库、支付、商城。

## 任务 1：普通摸牌后不自动打出

当前错误逻辑：

```txt
玩家普通摸牌后，如果摸到可出的牌，系统立即自动打出。

正确逻辑：

1. 玩家没有可出牌时点击摸牌。
2. 系统摸 1 张牌。
3. 这张牌先加入玩家手牌。
4. 如果这张牌可以打出，客户端弹窗询问：
   “刚摸到的牌可以打出，是否立即打出？”
5. 玩家点击“打出”才发送出牌命令。
6. 玩家点击“不打出”则保留手牌，并按规则结束或推进回合。

注意：

摸到技能牌也可以选择立即打出。

但只适用于：

普通摸牌阶段

不适用于：

罚抽
加牌链结算
质疑罚摸
UNO 罚摸
淘汰结算摸牌
任务 2：罚抽指定颜色一张一张摸

当前错误逻辑：

罚抽直到颜色命中时，系统一次性把所有牌摸完。

正确逻辑：

1. 玩家进入 drawUntilColor 状态。
2. 玩家点击“继续罚抽”。
3. 系统只摸 1 张。
4. 弹窗或提示显示：
   “罚摸红色，摸到的是蓝色，请继续摸。”
5. 如果摸到目标颜色：
   “罚摸红色，摸到的是红色，罚抽结束。”
6. 罚抽结束后推进回合。

要求：

每次罚抽只产生一张新牌。
每次都能触发摸牌动画。
每次都能显示颜色提示。
不允许中途打出罚抽摸到的牌。
罚抽过程中普通出牌按钮应禁用。
任务 3：刚摸到的牌红色圈出

要求：

刚摸到的牌在手牌区用红色圈出。

持续时间：

直到下一个完成出牌后消失。

需要区分：

红色圈 = 刚摸到
上移 = 当前选中
紫色框 = 顺子候选
黄色框 = 当前刚出的牌或加牌链

建议增加字段：

lastDrawnCardIdsByPlayer?: Record<PlayerId, CardId[]>

或者在客户端根据事件记录：

draw-card event -> 记录 cardId -> 红圈
play-card event -> 清理红圈

注意：

其他玩家不应该看到具体牌面，只能看到牌背或手牌数量变化。
任务 4：摸牌动画

要求：

摸牌时，牌从摸牌堆位置飞向玩家手牌区。

本地玩家视角：

牌背或牌面从牌堆飞到自己的手牌区
落下后插入手牌
刚摸到的牌红色圈出

其他玩家视角：

牌背从摸牌堆飞向该玩家头像或座位
该玩家手牌数量 +1

动画不要影响规则结果。
规则结果仍由服务端 snapshot 决定。

任务 5：质疑判定不计算刚摸到的牌

当前需求：

如果摸牌前手牌没有黑色牌，
摸牌后摸到黑色牌，
别人质疑时，仍然按摸牌前状态判定。

也就是说：

质疑判断基于摸牌前手牌。

要求：

普通摸牌前记录 hadBlackCardBeforeDraw。
质疑成功 / 失败使用这个字段。
不要扫描摸牌后的 hand 来判断。
玩家刚摸到的黑牌不能影响这次质疑结果。
质疑窗口关闭后清理该字段。
验收标准

完成后至少满足：

1. 普通摸牌后不会自动打出。
2. 普通摸牌后如果可打，弹窗询问是否立即打出。
3. 罚抽指定颜色每次只摸一张。
4. 每次罚抽都会提示“目标颜色 / 摸到颜色 / 是否继续”。
5. 刚摸到的牌有红色圈。
6. 下一个完成出牌后红色圈消失。
7. 摸牌有落入手牌区的动画。
8. 质疑判定不包含刚摸到的牌。
9. 罚抽、质疑罚摸、UNO 罚摸都不会弹出“是否打出”。
